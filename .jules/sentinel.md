## 2024-06-12 — 🛡️ Sentinel: Fix unbounded read DoS in wakeword payload parsing
**Learning:** Parsing JSON messages from a network stream without bounding the reported `payload_length` can lead to endless loops or unbounded memory allocation, causing Denial of Service. When reading `payload_length` from untrusted sources, always enforce a strict maximum size limit and raise an exception to terminate the parsing loop upon violation.
**Action:** Added a 5 MB maximum bound check for `payload_length` in `_drain_detections` and the socket `read_loop` implementations in `linux/blitztext/wakeword.py` and `linux/blitztext/wakeword_bench.py`, raising a `ValueError` if the length is excessively large. Also fixed CI secret scanner configuration to explicitly ignore dummy keys in documentation.
