## 2026-09-06 — [talk.py: Fix command injection in subprocess call]
**Learning:** `talk.py` uses `subprocess.Popen(cmd, shell=True)` with a command constructed from configuration variables and arbitrary data (which gets partially `shlex.quote`d, but is still vulnerable or improperly parsed). When `shell=True` is used for pipelines like `curl | ffplay`, it allows arbitrary command execution depending on the inputs, especially if JSON payload contains shell sequences that escape `shlex.quote` or are interpreted incorrectly by `curl` or `sh`.
**Action:** Removed `shell=True` and `shlex.quote` from `linux/blitztext/talk.py`. The `curl | ffplay` pipeline was refactored into two separate `subprocess.Popen` calls, chaining `p1.stdout` into the `stdin` of `p2`. This allows argument vectors to be safely passed without shell interpretation.
