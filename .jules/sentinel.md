## 2026-07-07 — Fix command injection in TTS playback
**Learning:** Found that `blitztext/talk.py` constructs a shell pipeline `curl ... | ffplay ...` using `shell=True`, passing raw URLs embedded into the command string. If a malicious user sets the active_talk URL in config to something like `http://example.com; malicious_command`, it results in command injection.
**Action:** Replaced the vulnerable shell string execution with chained, list-based `subprocess.Popen` pipelines (using `stdout=subprocess.PIPE` for `curl` and `stdin=p1.stdout` for `ffplay`). Removed manual `shlex.quote` escaping, relying on the subprocess list arguments to correctly escape and isolate all untrusted inputs. Added a targeted security test using `mock_popen.call_args_list` to explicitly assert that no shell wrappers are injected and the correct arguments are safely passed to the executable list.
